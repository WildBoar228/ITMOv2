Практика 4: две фичи с агентом — отчёт

Проект «Quiz-карточки» (Kahoot на одного): локальная страница, 15 с на вопрос, 4 варианта, без сохранения прогресса.
Запуск: python3 -m http.server 8000 → /project/ · Проверка: bash tests/check.sh → 20 passed, CHECK_OK

1. Настроенная среда 5 баллов

  1. AGENTS.md — AGENTS.md: структура, строгая схема decks.json (4 варианта, correct 0–3, опциональный explain), запреты (таймер 15 с, никакого localStorage для счёта), команды проверки. Агент читает его через instructions в opencode.json.
  2. Skill — свой quiz-generator (+ template.md) и готовый test-driven-development. Обоснование: генератор закрывает самое долгое — набивание вопросов; TDD задаёт процесс «сначала красный тест».
  3. MCP — внешний context7 (remote, корень репо) для свежих доков + свой quiz (local, mcp/quiz_server.py). Обоснование: агент работает с колодами строгими вызовами, а не правит JSON руками.
  4. Hook — .opencode/plugins/quiz-check.js на tool.execute.after (только edit/write внутри project/), runner — tests/check.sh (json.tool + node --check + pytest -q). Регистрация не нужна — файл подхватывается автоматически. Провал бросается исключением и виден агенту как ошибка тула.

2. Skill 2 балла

Устройство: инструкция + шаблон. Агент извлекает из учебного текста только проверяемые факты, собирает вопросы строго по шаблону и обязан прогнать самопроверку по тем же правилам, что validateDeck(), до выдачи. Ценность — игра импортируется в UI с первого раза.

Запуск и результат: демо — квиз из practice_04/README.md (валиден: validateDeck → [True]); боевое — игра «Реляционная алгебра (лекция 5)», 8 вопросов из внешнего конспекта db_lec5.md, добавлена в project/data/decks.json. Позиции correct выровнены вручную до [0,1,2,3,1,0,2,3].

3. Собственный MCP 2 балла

Полезный tool (на деле 4, read-only): list_decks, get_question (без correct — не подсматривать), check_answer (возвращает correct + explain), validate_deck (проверка JSON от quiz-generator перед импортом). Тесты: mcp/test_quiz_server.py — 10 шт., 10 passed.

Реальный вызов: opencode mcp list → ✓ quiz connected (stdio-транспорт доказан живым клиентом).

use quiz → list_decks → [{id: "demo-it", questionCount: 3}, ...]
check_answer(demo-it, q1, 0) → {correct: true, explain: "HTML — язык разметки..."}

Ошибочный вход: check_answer(demo-it, q1, 9) → error: answer_idx must be 0–3; get_question(nope, 0) → error: unknown deck. Все 4 ошибки покрыты тестами.

4. Фичи A и B

  • A — пояснения к ответам (цикл TDD: RED 2 failed → GREEN 6 passed): поле explain? в схеме, редактор, показ после ответа. По пути пойман и за skewness-пример: hook отвечал CHECK_FAIL после каждой правки до победного.
  • B — правка / удаление игр: кнопки ✎/🗑 на карточках, режим editingId, удаление через confirm(), всё в памяти. Тесты: tests/test_feature_b.py (4 шт.).

5. Рефлексия (кратко)

Проект придумали и написали вместе с агентом, но пришлось найти самому несколько багов. Очень эффективной была связка скилла для TDD + hook на тесты. Подробно — в reflection.md.
