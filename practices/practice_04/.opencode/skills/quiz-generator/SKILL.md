# Quiz Generator

Turn study notes (`.md`/plain text) into a game that imports into
Quiz-карточки on the first try — no schema fixes afterwards.

## When to use

- «Сделай игру/квиз/вопросы из ...», «нагенерируй карточки по лекции»
- Input: путь к `.md`/тексту + название игры. Нет файла — попроси вставить текст.

## Workflow

1. **Прочитай источник.** Выдели проверяемые факты: определения, числа,
   связи «термин — значение». Один факт = один вопрос. Фактов меньше, чем
   просят вопросов, — скажи об этом и не выдумывай недостающее.
2. **Собери вопросы по [template.md](template.md).** Ровно 4 варианта,
   `correct` — индекс 0–3, правильный ответ распределяй по разным позициям,
   дистракторы — правдоподобные (частые ошибки, соседние термины), `explain` —
   выжимка из источника (1–2 предложения), а не общие слова.
3. **Самопроверка (обязательно, до выдачи).** Прогони каждый вопрос по чек-листу:
   - `q`, все 4 `options`, `explain` (если есть) — trim, пустых нет
   - `correct` — целое 0–3 и указывает на фактически верный вариант
   - нет двух одинаковых вариантов, нет подсказки в формулировке
   - `id` вопросов уникальны (`q1`, `q2`, …)
4. **Выдача.** Один JSON-объект игры `{id, title, questions: [...]}`.
   По умолчанию — текстом в чат + предложение импортировать через кнопку
   «Импорт JSON» в UI. В `project/data/decks.json` руками не пиши без просьбы.
5. **Подтверждение.** После выдачи скажи, как проверить:
   `pytest -q` (схема) и импорт в UI. Если пользователь просит — сам запусти
   проверку и покажи результат.

## Don'ts

- Не выдумывай факты, которых нет в источнике.
- Не делай меньше 4 или больше 4 вариантов «для разнообразия».
- Не клади в `explain` новый проверяемый факт, которого нет в вариантах, —
  пояснение объясняет ответ, а не задаёт следующий вопрос.
