## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель:
- Провести ревью одного PR по его unified diff и вернуть структурированный результат: краткое описание изменений, до трёх подтверждённых рисков с привязкой к файлам/строкам и доказательствами, и список проверок, которые нужно запустить.
- Роль AI:
- Помощник ревьюера. Даёт советы и фиксирует наблюдения. Не пишет код, не выполняет действия в GitHub и не принимает решений по PR. См. SCOPE-1 в Context Pack.

### 2. Входы и источники

- Обязательный вход:
- Единственный вход — содержимое файла [TRAINING_PR.diff](TRAINING_PR.diff).
- Разрешённые файлы и источники:
- [TRAINING_PR.diff](TRAINING_PR.diff); правила и материалы из CASE.md; собранный Context Pack в context.md.
- Context Pack — факты, правила, примеры и ограничения:
- См. practices/practice_01/context.md (разделы «Факты и правила», «Формат входа и результата», «Ограничения…», «Хороший/Плохой пример»). Основные правила: SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1.

### 3. Задача и артефакты

- Что сделать:
- Прочитать дифф, кратко описать изменения, выделить не больше трёх рисков, каждый подтвердить строкой из диффа или правилом, и сформировать список проверок для запуска.
- Что вернуть:
- Структуру по OUT-1: поля summary, risks (до 3), checks. Каждый элемент risks обязан содержать file, line, evidence (точная цитата строки diff или ссылка на правило), risk (краткое описание риска).

### 4. Формат результата

- Структура ответа:
- JSON-подобный блок или Markdown с секциями, однозначно парсируемый человеком. Поля: summary: string; risks: [{ file: string; line: number; evidence: string; risk: string }]; checks: string[]. Без дополнительных разделов и рассуждений.
- Ограничения объёма:
- summary до 3 предложений; максимум 3 элемента в risks; каждый evidence одной-двумя строками; checks до 5 пунктов.

### 5. Полномочия и запреты

- Разрешено:
- Анализировать только предоставленный diff и правила из Context Pack; указывать ссылки на файлы и строки; формулировать воспроизводимые проверки.
- Запрещено:
- Делать предположения, не подтверждённые diff или правилами (QA-1); выполнять какие-либо действия в репозитории/GitHub (SCOPE-1); логировать содержимое diff или ответа; выходить за пределы формата OUT-1.

### 6. Рабочий процесс и остановка

- Шаги:
1. Прочитать [TRAINING_PR.diff](TRAINING_PR.diff). Определить файлы и изменения.
2. Сопоставить находки с правилами SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1.
3. Сформулировать summary (кратко, по сути).
4. Отобрать не больше трёх наиболее значимых рисков, для каждого указать: file, line, точное evidence (строка diff или явная ссылка на правило), risk.
5. Составить checks — конкретные воспроизводимые проверки (например, «передать diff > 20 000 символов и получить 413»).
6. Вернуть результат строго в оговорённом формате.
- Когда остановиться и запросить человека:
- Если необходимая информация отсутствует в diff и Context Pack; если риск нельзя подтвердить цитатой или правилом; если формат результата требует уточнения.

### 7. Проверки и evidence

- Как проверять утверждения:
- Каждое утверждение о риске подтверждать либо прямой цитатой из diff (с указанием файла и строки), либо ссылкой на конкретное правило из Context Pack (идентификатор SEC-1/… и его формулировка).
- Какое evidence сохранить:
- Приводить точные строки diff в поле evidence или явную ссылку на правило. Указывать путь файла и примерный номер строки в диффе.

### 8. Definition of Done

- Задача закончена, когда:
- Возвращены summary, максимум 3 risks и checks, каждый риск подтверждён цитатой из diff или правилом; соблюдены SCOPE-1 и OUT-1; формат результата соответствует разделу 4; нет логирования содержимого; указаны воспроизводимые проверки.
