# Проблема и метрики

## Проблема

- Пользователь: инженеры-ревьюеры и/или CI, вызывающие POST /api/reviews для автоматической первичной проверки PR.
- Ситуация: внедрён новый endpoint и сервис, передающий diff во внешний LLM и возвращающий ответ, но без соблюдения правил SEC-1, API-1, OUT-1 и частично REL-1 из Context Pack.
- Что происходит сейчас: сервис отправляет полный diff во внешний LLM без маскирования секретов; API не ограничивает размер входа; ответ формируется как произвольное поле comment вместо требуемой структуры; обработка таймаутов/ошибок внешнего LLM не нормализована; валидация отсутствующих полей не оформлена как 422.
- Почему это мешает пользователю или бизнесу: высокий риск утечки секретов, нестабильность и непредсказуемость времени ответа, невозможность машинной обработки результата (несоответствие OUT-1), отсутствие предсказуемого поведения для больших входов и пустых тел запроса; это ломает интеграции в CI и повышает операционные риски.
- Что не входит в задачу: аутентификация и авторизация, рейтлимитинг, квоты, сохранение истории ревью, интеграция с внешними системами, переработка бизнес-логики вне перечисленных правил, любые действия в репозитории/GitHub.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля ответов API в формате OUT-1 | Проверка схемы ответа в тестах | 100% ответов соответствуют схеме | На каждом CI-прогоне | Автотесты OUT-1 |
| Утечки секретов в prompt | Тест с синтетическим секретом; проверка маскирования | 0 утечек | На каждом CI-прогоне | Unit/Integration для SEC-1 |
| Обработка длинных diff | Тест с 20001 символом | 100% запросов получают 413 | На каждом CI-прогоне | Integration/API тесты |
| p95 времени ответа | Замер при штатной нагрузке с заглушкой LLM | ≤ 10 секунд | До релиза и периодически | Наблюдения в тестах/локальные метрики |
| Доля 422 при отсутствии поля diff | Отправка запроса без diff | 100% возвращают 422 | На каждом CI-прогоне | API тесты валидации |

## Почему изменение метрики подтвердит решение проблемы

Метрики напрямую отражают соблюдение правил: OUT-1 (структурированный ответ), SEC-1 (маскирование секретов), API-1 (ограничение размера), REL-1 (таймауты и контролируемый ответ) и корректная валидация входа. Достижение целевых значений гарантирует пригодность сервиса для интеграции в CI и снижает риски.
