## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413.
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- OUT-1: ответ содержит summary, массив risks (максимум 3 элемента с полями file, line, evidence, risk) и массив checks.
- SCOPE-1: помощник только советует; он не пишет код и не выполняет действия в GitHub.
- QA-1: риск включается в ответ только если он подтверждён строкой diff или правилом репозитория.
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа модели не логируется.

### Формат входа и результата

- Вход: один unified diff PR (файл TRAINING_PR.diff).
- Результат: объект с полями summary (краткое описание изменений), risks (до 3 элементов с file, line, evidence, risk), checks (список проверок для запуска). См. OUT-1.

### Ограничения и запрещённые действия

- Соблюдать SCOPE-1: не выполнять действия в репозитории/CI/GitHub, не писать/менять код.
- Не добавлять не подтверждённые предположения; каждый риск должен ссылаться на строку diff или правило (QA-1).
- Не логировать содержимое diff и ответ модели (OBS-1).
- Соблюдать ограничение размера входа (API-1) и таймаут внешнего вызова (REL-1).
- Редактировать/маскировать потенциальные секреты в diff перед отправкой в LLM (SEC-1).

### Хороший пример


app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
### Плохой пример


Код можно улучшить. Добавьте тесты и обработку ошибок.
### Что пока неизвестно

- Полный контекст репозитория и реализованные механизмы защиты (аутентификация, рейтлимит, квоты).
- Фактическая реализация LLM-клиента (синхронный/асинхронный интерфейс, политика ретраев).
- Точный формат и источники логов/метрик, кроме ограничений OBS-1.
- Требования к структуре ответа сверх OUT-1 (например, сортировка рисков по критичности).

## Как использовали AI

- Для чего: baseline-ревью учебного diff для выявления проблем и рисков
- Тип промпта: zero-shot
- Строка в [`prompts.md`](prompts.md): таблица «Журнал запросов и проверок», запись с ID P1-01
- Что проверили и исправили сами: отфильтровали предположения вне контекста diff и правил; сфокусировали вывод на подтверждённых рисках, устранили спекуляции вроде несовместимости версий Python; отметили необходимость структурированного ответа по OUT-1
