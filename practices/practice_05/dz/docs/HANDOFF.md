# HANDOFF — фича B: правка / удаление игр

## Состояние

Реализовано и зелено. На каждой карточке списка рядом с «Играть» две кнопки:
`✎` загружает игру в редактор (заголовок «Редактирование», «Сохранить»
обновляет deck по `id`), `🗑` удаляет через нативный `confirm()`.
Всё в памяти; персист — только через существующую кнопку «Скачать все игры».

Контракт режима правки: `state.editingId` (`null` = новая игра).
`startEdit(id)` → заполняет редактор из deck; `openNewEditor()` → чистый
редактор для новой игры; `save-deck` при `editingId` заменяет deck по
`findIndex` с сохранением `id` (`{...deck, id: editingId}`), затем сбрасывает
`editingId`; удаление — `deleteDeck(id)` с `confirm()`, отмена = ничего.

## Ограничения

- Нет персиста правок/удалений: перезагрузка страницы возвращает исходные
  `data/decks.json` (так задумано — см. правило 4 в `AGENTS.md`).
- Удаление колоды во время её прохождения не блокируется и забег не трогает;
  ретрай после удаления молча ничего не делает (`startGame` не находит `id`).
- Если редактируемая колода исчезла до сохранения (`idx < 0`) — сохранение
  создаёт новую запись, а не падает.
- `aria-label` кнопок содержит название игры как есть (без экранирования —
  `setAttribute`, не `innerHTML`, XSS нет, но кавычки в title без обработки).
- Тесты фичи B — статические проверки исходника (DOM-рантайм без зависимостей
  не покрыт); при смене имён функций/классов обновить `test_feature_b.py`.
