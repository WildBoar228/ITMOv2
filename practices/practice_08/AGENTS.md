# Практика 8: Quiz-карточки

Учебное приложение для самостоятельной проверки знаний: пользователь создаёт наборы вопросов и проходит викторины. Полное задание и критерии сдачи — в `README.md` этой практики.

## Структура и текущая логика

- `project/index.html` — экраны списка игр, редактора, викторины и результата.
- `project/app.js` — загрузка `data/decks.json`, создание и редактирование игр, импорт/экспорт JSON, таймер и подсчёт очков.
- `project/style.css` — стили; `tests/` — каталог для проверок.
- Сейчас используются HTML, CSS и JavaScript без библиотеки компонентов. Изменения игр и прогресс хранятся только в памяти страницы.

## Основной пользовательский сценарий

Пользователь хочет проверить знания по выбранной теме и увидеть результат.

1. Открывает список игр и выбирает «Играть» у нужного набора.
2. Видит вопрос, четыре варианта ответа и таймер на 15 секунд.
3. Выбирает ответ; приложение блокирует повторный выбор, показывает правильный вариант, обратную связь и пояснение, если оно задано. При истечении времени показывает «Время вышло!».
4. Нажимает «Далее» и проходит остальные вопросы. За правильный ответ получает 10 очков плюс оставшиеся секунды с округлением вверх.
5. Нажимает «К результату» и видит итоговые очки и число правильных ответов. Может пройти игру ещё раз или вернуться к списку.

Дополнительный сценарий: «+ Новая игра» → название, хотя бы один вопрос, четыре заполненных варианта и правильный ответ → сохранение → новая игра в списке → прохождение.

## Требования к доработке

- Сохраняй связь интерфейса с реальной логикой приложения и формат данных существующих игр.
- Подготовь макет основного сценария и его состояний; выбранную библиотеку компонентов и команды запуска укажи в README проекта.
- Предусмотри загрузку, пустой список, успех и понятную ошибку с повторной попыткой; ошибку загрузки не выдавай за пустой список.
- Обеспечь подписи полей, видимый фокус, управление с клавиатуры и удобство на узком экране.
- Проверяй видимое поведение: полный сценарий, валидацию редактора, состояния загрузки данных и защиту от повторных действий. В клиентских тестах подменяй ответы загрузки данными реального формата.
- Фиксируй использование AI, внесённые исправления и результаты запуска клиентских тестов согласно заданию.
