# Практика 8: Quiz-карточки

Учебное приложение для самостоятельной проверки знаний: пользователь создаёт наборы вопросов и проходит викторины. Полное задание и критерии сдачи — в `README.md` этой практики.

## Структура и текущая логика

- `project/src/App.jsx` — навигация, загрузка игр, импорт/экспорт JSON и удаление.
- `project/src/components/` — список, редактор, викторина и результат; `project/src/decks.js` — валидация и общая логика данных.
- `project/public/data/decks.json` — исходные игры; `project/src/style.css` — токены темы и стили.
- `project/src/components/ui/` — готовые компоненты shadcn/ui, добавленные CLI; конфигурация — `project/components.json`. Переиспользуй их при доработке интерфейса.
- Стек: React + Vite + shadcn/ui + Tailwind CSS, JavaScript. Изменения игр и прогресс хранятся только в памяти страницы.
- Внешний вид — по `prototype.html` и `prototype_screenshots/`: светлая палитра, пастельные карточки, модальные редактор и игра. Оболочка на английском, исходные вопросы на русском.
- Команды из `project/`: `npm ci`, `npm run dev`, `npm run build`. Подробности — в `project/README.md`. Клиентские тесты пока не добавлены.

## Основной пользовательский сценарий

Пользователь хочет проверить знания по выбранной теме и увидеть результат.

1. Открывает список игр и выбирает «Play quiz» у нужного набора.
2. Видит вопрос, четыре варианта ответа и таймер на 15 секунд.
3. Выбирает ответ; приложение блокирует повторный выбор, показывает правильный вариант, обратную связь и пояснение, если оно задано. При истечении времени показывает «Time’s up!».
4. Нажимает «Next question» и проходит остальные вопросы. За правильный ответ получает 10 очков плюс оставшиеся секунды с округлением вверх.
5. Нажимает «To the result» и видит итоговые очки, число правильных ответов и точность. Может пройти игру ещё раз или вернуться к списку.

Дополнительный сценарий: «New game» → название, хотя бы один вопрос, четыре заполненных варианта и правильный ответ → «Save game» → новая игра в списке → прохождение. Категория, описание, эмодзи и пояснения необязательны; цвет обложки выбирается в редакторе. Предпросмотр обложки обновляется при вводе.

## Требования к доработке

- Сохраняй связь интерфейса с реальной логикой приложения и формат данных существующих игр.
- Подготовь макет основного сценария и его состояний; выбранную библиотеку компонентов и команды запуска укажи в README проекта.
- Предусмотри загрузку, пустой список, успех и понятную ошибку с повторной попыткой; ошибку загрузки не выдавай за пустой список.
- Обеспечь подписи полей, видимый фокус, управление с клавиатуры и удобство на узком экране.
- Проверяй видимое поведение: полный сценарий, валидацию редактора, состояния загрузки данных и защиту от повторных действий. В клиентских тестах подменяй ответы загрузки данными реального формата.
- Фиксируй использование AI, внесённые исправления и результаты запуска клиентских тестов согласно заданию.
